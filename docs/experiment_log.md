# Experiment Log

One row per experiment, audit or check. Rules:
- Write the hypothesis **before** running. Add the outcome afterwards, and never edit a hypothesis after seeing results.
- Every number traces to a saved file or a commit. Mark analyses done after seeing test results as **post-hoc**.
- Test sets are used once per frozen model. A later change to a frozen model is a new experiment on a new run.

Types: **experiment**, **audit** (checks the data or the pipeline), **post-hoc**, **verification** (software, no new results).

## P01 design

Fixed before any P01 model is trained. Changing any item below after seeing a P01 result makes the result post-hoc.

**Arms** (all use `splits/all.csv`; the test sets are used once, after freezing):
- **Image-only:** ResNet-18 with the Baseline B recipe (`configs/image_model.yaml`), photograph only.
- **Combined (primary):** the same network and recipe. The three predicted ratios (vertical, horizontal, area CDR) are standardised with training-set statistics and joined to the 512 pooled image features before the final layer. Nothing else differs from the image-only arm.
- **Measurements-only:** frozen Baseline A (`docs/frozen_baseline_a_common_split.json`), not retrained.

**Inputs.** Ratios come from the frozen Baseline A U-Net, never from expert masks. They are computed for every image of the classification split, including those without expert masks (the U-Net needs only the photograph and no labels). Images with no detected disc get the training median, as in Baseline A; their results are also reported separately.

**Training and seeds.** Each arm is trained with 5 seeds (2440 to 2444). Epoch selection and early stopping follow Baseline B (best validation AUROC) and use CHAKSU validation only. All runs happen on the same GPU type. Each run records its commit, library versions and device.

**Scores.** The primary score of an arm is the mean of its 5 seeds' logits per image. The per-seed AUC differences are reported alongside, to show training variability.

**Primary comparison.** Combined minus image-only, AUC, on CHAKSU test and PAPILA separately and never pooled. Paired bootstrap, 2,000 resamples of whole `analysis_group`s, 95% interval, seed-averaged scores. Improvement only if the interval excludes 0. A difference with an interval that includes 0 is reported as "not shown", not as "no effect".

**Secondary comparisons** (reported, not used for the headline claim):
- Combined vs measurements-only on the images they share: does the photograph add to the measurements?
- **Two-step blend:** image scores cross-fitted over 5 grouped folds of the development data (same 5 seeds, fold assignment seed 2440, fixed epoch count taken from the validation-only development run), then a logistic regression on the image score plus the three ratios, against the cross-fitted image score alone. Run after the primary result is recorded.
- Sensitivity and specificity at the Baseline B threshold rule (90% sensitivity on validation), descriptive only.

**Stated caveats.**
- CHAKSU labels follow CDR closely, so a CHAKSU gain may be circular; PAPILA is the more informative test.
- The network may lean on the ratios and learn little from the image. The comparison with measurements-only shows whether the image still adds anything.
- Training-set ratios come from images the U-Net learned from, so they are slightly cleaner than on new images.
- With 50 CHAKSU and 85 PAPILA test positives, only fairly large differences are detectable.
- The image-only arm is a new run, not the E07 checkpoint, which is kept as the earlier reference.

**Freeze.** Configs, code commit, split and measurement files are recorded with SHA-256 before the test sets are opened, using the same mechanism as Baseline A.

## P01b design

Fixed on 2026-11-14, before any P01b model is trained. The experiment was pre-registered as a secondary comparison of P01 and is run now because P01 did not show an improvement (E13) and the likely reason is that the network fitted the training labels from the photograph alone. The test sets were already used by earlier experiments, so P01b is exploratory evidence on them. Changing any item below after seeing a P01b result makes the result post-hoc.

**Question.** Do the three predicted cup-to-disc ratios improve an image score that was never fitted on its own images?

**Data.** Development images are the classification train and validation images of `splits/all.csv` (1,008). The CHAKSU test set and PAPILA are scored once, after freezing.

**Image model.** The P01 image-only recipe (`configs/p01_image_only.yaml`: ResNet-18, ImageNet start, batch 16, head learning rate 1e-4, backbone 1e-5, colour jitter). Training length is fixed at **10 epochs** (2 head-only, then 8 of fine-tuning), the median best epoch of the five P01 image-only runs (8, 10, 11, 8, 11; validation only). There is no early stopping and the last epoch is used.

**Cross-fitting.** The development images are split into 5 folds that keep every `analysis_group` together and balance the labels (the Baseline A routine `grouped_folds`, fold seed 2440). For each of the 5 seeds (2440 to 2444), 5 networks are trained, each on 4 folds, and each scores the fold it did not see. That gives 25 checkpoints. The **out-of-fold image score** of a development image is the mean logit over the 5 seeds of the network that never saw it.

**Test image score.** The mean logit over all 25 networks.

**Blend.** The Baseline A classifier (median fill, standardise, logistic regression with balanced class weights) on four inputs: the image score and the three ratios from the same predicted-ratio file as P01 (`runs/p01/measurements.csv`). The regularisation strength C comes from the Baseline A grid (0.001 to 100) by grouped 5-fold cross-validated AUC on the development images (fold seed 2440). The final blend is fitted on all 1,008 development images.

**Primary comparison.** AUC of the blend minus AUC of the image score alone, on CHAKSU test and PAPILA separately, never pooled. Paired bootstrap over whole `analysis_group`s, 2,000 resamples, 95% interval (the P01 routine). An improvement is claimed only if the interval excludes 0.

**Secondary comparisons.**
- Blend against measurements-only (frozen Baseline A) on the images they share.
- Development diagnostic, before freezing and not a decision rule: out-of-fold AUC of the image score alone against the cross-validated AUC of the blend on the development images.

**Stated caveats.**
- Development image scores come from single networks trained on 80% of the data, while test image scores average 25 networks. The two have different spread, which can shift the blend's weights. This is usual in stacking and is not corrected.
- CHAKSU labels follow CDR closely, so a CHAKSU gain may be circular; PAPILA is the more informative test.
- The ratios of development images come from a U-Net that was trained on them (as in P01).
- With 50 CHAKSU and 85 PAPILA test positives only fairly large differences are detectable.

**Freeze.** All 25 checkpoints, the fitted blend, the measurements file and the split file are recorded with SHA-256 and the code version before the test sets are opened. Scoring refuses to run twice.

## X-series design

Fixed on 2026-11-14, before any X experiment is run. Motivation: E13 and E14 show that the photograph alone reaches 0.78 to 0.81 AUC, the three ratios reach 0.94 on CHAKSU but only 0.73 on PAPILA, and the PAPILA drop traces to cup conventions, segmentation shift, disc scale and a network that memorises its training labels (Baseline A write-up, "Why PAPILA failed"). The methods below come from the literature on cross-dataset glaucoma screening: foundation-model backbones (GONet, DINOv2 against RETFound), multi-task learning with disc and cup segmentation (Pascal et al. 2022), and unsupervised adaptation of disc and cup segmentation (SCUDA, DDS-UDA; batch-norm adaptation as in TENT).

**Rules for the whole series.**
1. Order: X1, X2, X3, X4, X5, X6, X7. Each is attempted once. Every result is logged, including nulls.
2. **Development gate.** Before an experiment touches a test set it must pass a gate on development data only. A gate run trains on Remidio images of train only (646), picks the epoch on Remidio validation images, and scores the other cameras' development images (Bosch and Forus, train and validation, 198 images, 35 glaucoma). This stands in for "a new camera". Three seeds (2440 to 2442), the baseline run the same way. The variant passes if its mean AUC is above the baseline's. The proxy is small and keeps CHAKSU's label convention, so it cannot stand in for PAPILA labels. A variant that fails is dropped and never scored on a test set.
3. A variant that passes is frozen (code version and SHA-256, `freeze.py`) and scored once on CHAKSU test and PAPILA, separately, never pooled. Image variants use the P01 protocol: 5 seeds (2440 to 2444), validation picks the epoch, seed-averaged scores, paired bootstrap over `analysis_group` (2,000 resamples). Baseline for image variants: the P01 image-only arm (0.813 CHAKSU, 0.764 PAPILA). Baseline for measurement variants: frozen Baseline A (0.943, 0.731).
4. An improvement is claimed only if the 95% interval excludes 0. Both test sets were already used by earlier experiments, and up to 14 test-set comparisons can be made in this series, so any single win is exploratory and only independent data would confirm it. The write-up states how many comparisons were made.
5. PAPILA labels are never used for training or choosing settings. X1 and X5 use unlabelled PAPILA photographs (their ratios or pixels, not their labels) to adapt; these are reported as "label-free adaptation", apart from the rest.
6. After a result is seen nothing is changed or re-run, except a bug that is disclosed (as in E13). Settings below are fixed now.

**X1. Per-dataset standardisation of the ratios.** Each ratio (vertical, horizontal, area CDR) is z-scored with the mean and standard deviation of its own dataset's images: CHAKSU development images for the classifier fit, CHAKSU test images for CHAKSU test, PAPILA images for PAPILA. The classifier, C and threshold are those of frozen Baseline A, refitted on the z-scored CHAKSU development ratios. Because a z-score is a linear rescaling it moves the operating point more than the ranking, so the primary metric is balanced accuracy at the frozen threshold (sensitivity and specificity averaged); AUC is secondary and expected to move only through the relative weights of the three ratios. The gate: train on Remidio z-scored within camera, score the Bosch and Forus development images z-scored within their cameras, compare balanced accuracy with the unstandardised version. Caveat: dataset prevalence also shifts the mean (13% against 20% glaucoma).

**X2. Disc-centred crop.** The frozen Baseline A U-Net gives a predicted disc for each image. The crop is a square of side 3 times the disc's longer side, centred on the disc centroid, cut from the 512 px segmentation image and resized to 224 px. Images with no predicted disc (30 in PAPILA) use the full image. Network, recipe and seeds as in P01 image-only. Crops are written to `runs/` and never committed.

**X3. Stronger augmentation and normalisation.** The full photograph, with stronger colour jitter (brightness, contrast, saturation 0.4, hue 0.1), random gamma, random greyscale 0.1, and per-image mean and standard deviation normalisation per channel. Otherwise as P01 image-only.

**X4. Foundation-model backbone.** DINOv2 ViT-B/14 (public weights, ImageNet-scale natural images, no retinal pretraining) replaces the ResNet-18. Stage 1: frozen features and a logistic regression (descriptive). Stage 2, primary: fine-tuning with a head learning rate of 1e-3 and a backbone learning rate of 1e-5, 2 head-only epochs then fine-tuning, 224 px input. If the weights cannot be obtained or the licence forbids it, X4 is logged as not run, with the reason. RETFound is not used because its weights are access-controlled.

**X5. Robust segmentation.** The Baseline A U-Net(ResNet-34) retrained on CHAKSU train with random scale (0.6 to 1.6), stronger colour augmentation and the same loss and schedule, plus re-estimation of the batch-norm statistics on the unlabelled images of each target dataset at inference. Gate: Dice on the Bosch and Forus development images of a CHAKSU-Remidio-only run, and no loss of more than 0.01 Dice on Remidio validation. Evaluation: Dice on both test sets, then the Baseline A classifier on the new measurements, AUC difference against frozen Baseline A.

**X6. Multi-task network.** U-Net(ResNet-34) encoder, classification head on the pooled bottleneck features, loss = binary cross-entropy for glaucoma plus the Baseline A segmentation loss, equal weights. Trained on images that have both labels. Indira's plan includes anatomy-supervised networks, so this runs only after we agree with her which of us does what; otherwise it is logged as "not run, overlaps".

**X7. Final blend.** Only if at least one of X1 to X5 passes the gate and shows an improvement. The best image variant (by test-independent gate result) is cross-fitted exactly as in P01b, the best measurement variant supplies the ratios, and the P01b blend and rule are used. Compared against the best single-input result.

**Stated limits.** The gate proxy has 35 positives and cannot reflect PAPILA's label convention. Variants may fail the gate for noise reasons and are then not tested. Seeds cover training variability; the intervals cover test-image sampling only.

**X1 clarification (written before any X1 result, after the gate design).** Both arms of X1 are refitted with the Baseline A recipe on the same 335 and 420 test images and the same development images: one on the ratios as measured, one on the standardised ratios. C comes from grouped cross-validated AUC and the threshold from Youden's J on out-of-fold development scores, in each arm. This replaces "the threshold of frozen Baseline A", which cannot apply to rescaled inputs, and gives a paired comparison on identical images. Standardisation is within the development images, within CHAKSU test and within PAPILA. Frozen Baseline A (0.943, 0.731) stays as the reference.

**X2 clarification (written after generating the crop boxes and before any X2 training).** The boxes come from the frozen Baseline A U-Net on every classification image. Six PAPILA images got a box under 100 px (as small as 27 px; the smallest CHAKSU box is 147 px), which is a spurious blob and not a disc. A box under 100 px is therefore treated as "no disc found" and the image keeps its whole photograph, like the 30 images with no predicted disc. Boxes are 3 times the disc's longer side, so after cropping the disc takes the same share of every image (PAPILA boxes average 299 px, CHAKSU 212 px).

**X5 clarification (written before any X5 code was run).** *Robust augmentation:* with the usual random horizontal flip, the image and masks are rescaled together by a factor drawn uniformly from 0.6 to 1.6 and then cut (factor above 1, random position) or padded with black (factor below 1, random position) back to 512 px; the image alone gets contrast 0.6 to 1.4, brightness plus or minus 0.2, a gain of 0.85 to 1.15 on each colour channel and gamma 0.7 to 1.4. Loss, optimiser, 40 epochs, batch size 8 and the learning rate are those of Baseline A. *Batch-norm re-estimation (AdaBN):* on the set being evaluated, the running statistics of every batch-norm layer are reset and re-estimated as a cumulative average over one pass of that set's unlabelled photographs (batch size 8, no weight changes, no labels or masks read); the set being evaluated is always the adaptation set (Remidio validation, the Bosch and Forus development images, CHAKSU train and validation, CHAKSU test, PAPILA). *Gate:* three seeds (2440 to 2442) of each arm trained on Remidio train segmentation images only, epoch chosen by Remidio validation Dice (mean of disc and cup, plain model). The variant arm is robust augmentation and is evaluated with AdaBN; the baseline arm is the Baseline A recipe, evaluated without. Score: mean of disc and cup Dice on the Bosch and Forus development images. The variant passes if its mean over seeds is above the baseline's and its Remidio validation Dice is no more than 0.01 lower. Descriptive only (no decision): the variant without AdaBN. *Evaluation if it passes:* one network, seed 2440, trained on CHAKSU train (epoch by CHAKSU validation), frozen with the Baseline A classifier recipe refitted on its own development measurements (AdaBN on CHAKSU train and validation), then scored once on CHAKSU test and PAPILA, each adapted on its own photographs. Primary: AUC of this pipeline minus frozen Baseline A (0.943 and 0.731, `runs/final/common_split/scores.csv`), paired bootstrap over analysis groups. Dice and the vertical CDR agreement are reported against Baseline A's. One network per arm means training variability is not covered by the interval, as for Baseline A.

**X6 clarification (written before any X6 code was run; the user asked for X6 to be run although the plan said to agree it with Indira first).** Indira's branch (`codex/indira-anatomy-experiments`) holds anatomy-supervised CNN code and a plan but no results, and it uses its own protocol, so X6 is run here under the X-series rules and is not a substitute for her work. *Network:* U-Net(ResNet-34) with the ImageNet-pretrained encoder and a glaucoma head (global average pool of the deepest encoder features and one linear unit), input the 512 px photograph. *Loss:* Baseline A's Dice plus cross-entropy on the masks plus binary cross-entropy on the glaucoma label, equal weights. *Training:* AdamW, learning rate 3e-4 with cosine decay, weight decay 1e-4, batch size 8, 30 epochs, the standard segmentation augmentation (flip, brightness and contrast); only images with both a label and expert masks are used for training (the number of training images that this leaves out is reported with the result), validation and test images need no masks. The epoch is the one with the highest validation AUROC of the glaucoma output. *Gate:* three seeds (2440 to 2442) trained on Remidio train images and scored on the Bosch and Forus development images. The baseline arm is the P01 image-only recipe, whose three gate runs were already done for X2 to X4 (identical code, data and seeds, so the same scores); its scores are copied into `runs/x6/gate/`. The variant passes if its mean AUC is above the baseline's. *Evaluation if it passes:* five seeds (2440 to 2444) on CHAKSU train, frozen, scored once on CHAKSU test and PAPILA (335 and 420 images), seed-averaged logits, paired bootstrap against P01 image-only as for X2 to X4.

**X7 clarification (written before any X7 ratio was computed or scored).** *Image score:* the cross-fitted P01b image scores are reused (the 25 P01b networks and their saved held-out and test logits); no image variant qualified, since X2 to X4 were dropped at the gate, so none is cross-fitted again. If X6 improves on the image-only model, a cross-fitted X6 blend is not run here and is listed as a limit. *Ratios:* the frozen X5 network (`docs/frozen_x5.json`), with batch-norm statistics re-estimated on each split's photographs (CHAKSU train, validation, test and PAPILA separately), gives the three ratios for every classification image; no label or mask is read. The file is written before the blend is fitted and is frozen with it. *Blend:* the P01b recipe unchanged (logistic regression on the image score and the three ratios, C by grouped cross-validation, fitted on all development images). *Test comparison:* AUC of the X7 blend minus the X5 measurements-only pipeline (the best single-input measurement result), paired bootstrap over analysis groups on the images both have scored (labelled images with expert masks: 326 CHAKSU test and 418 PAPILA); interval must exclude 0. Descriptive comparisons, with no decision attached: minus the image score, minus the P01b blend (old ratios) and minus frozen Baseline A. Test sets are scored once.

**X4 clarification (written before any X4 training).** DINOv2 comes from `timm` (`vit_base_patch14_dinov2.lvd142m`, Apache-licensed, 224 px input with interpolated position embeddings). The "linear-probe stage" is the existing 2-epoch head-only warm-up, whose validation AUROC is read from each run's `history.csv` (validation data, descriptive); there is no separate logistic-regression probe.
