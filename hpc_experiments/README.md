# HPC main-model experiments

Branch: `anatomy-experiments`. Keep the experiments here until team review; do not merge into main as part of running the sweep.

The objective is to test whether anatomical supervision and predicted cup-to-disc ratios improve the image-only reference. No improvement is assumed in advance. No real-data experiment results have been generated by this package yet.

Starting point: current main commit `194a005`. The team's completed P01 (`docs/combined_model.md`) concatenated ratios from the frozen U-Net with CNN features and did not establish an improvement. This new study instead supervises an image-derived CDR regression head jointly with classification, then ablates fusion. It is not a repeat of P01 or a claim that P01 succeeded. The hypotheses below are fixed before these new runs, after prior P01/test outcomes have been observed.

## Main architecture

```text
224px RGB photograph -> ImageNet ResNet-18 -> image features -----------+
                                           |                         |
                                           +-> 3 predicted CDRs -----+-> binary classifier
                                                  |
                              training only: compare to mask-derived CDRs
```

The CDR head predicts vertical, horizontal and area cup-to-disc ratios using sigmoid outputs. Fusion concatenates these predictions with pooled image features before a linear binary classifier. Classification loss is unweighted BCE; anatomy loss is 0.5 times Smooth L1 over valid targets only. CDRs come from the expert development masks, never from test masks. The input signature at inference accepts only an RGB tensor; true anatomical values cannot be passed to the classifier. No segmentation network is required at inference for this experiment.

This is direct measurement regression plus classification, not the original full contour-producing system. The existing segmentation baseline supplies a separate contour pathway. Since the predicted ratios are functions of the image features, fusion adds an anatomical constraint/parameterization rather than an independent imaging modality. Improvements must be measured.

The main controlled comparisons are **E3 versus E0** (auxiliary supervision) and **E4 versus E3** (predicted-ratio fusion). E4 versus E0 measures the combined extension.

| ID | Configuration | Control | Question |
|---|---|---|---|
| E0 | ResNet-18, image classification | Reference | What does the matched runner achieve? |
| E1 | ResNet-18, fine-tune layer4 only after warm-up | E0 | Does freezing early blocks reduce overfitting? |
| E2 | EfficientNet-B0 image classifier | E0 | Does another compact architecture help? |
| E3 | ResNet-18 + supervised CDR head; classifier uses image features | E0 | Does anatomy supervision help? |
| E4 | E3 + classifier receives predicted CDRs | E3 | Does explicit predicted-anatomy fusion help? |
| E5 | E4 + stronger brightness/contrast/saturation jitter | E4 | Does photometric augmentation help validation robustness? |

E2 is an architecture comparison, not an isolated loss ablation: backbone, pretraining recipe, parameter count, and native dropout differ. E5 is an augmentation study, not demonstrated domain generalization. No random crops or orientation changes are used. Existing black letterboxing and ImageNet normalization are retained; torchvision's default center-crop transform is not used.

## Protocol fixed before new runs

- Current common manifest `splits/all.csv`: SHA-256 `4590df4ee6e6ce8ed722786cdb49220b632468184222fb9760c396e5cbf37094`.
- Compared with the older `1937faba...` baseline manifest, all 1,833 image IDs agree on split, analysis group, classification labels/eligibility, image/mask paths, segmentation eligibility, camera and patient ID. The metadata file is not byte-identical and its original pixel hashes differ for many rows. The runner uses the current committed file and records the actual prepared development-image content hash for each run; the summarizer refuses to pool differing prepared exports.
- Training: 808 CHAKSU images (109 positive); validation: 200 (28 positive). Known group checks apply; unknown CHAKSU patient linkage remains unresolved.
- Seeds: 2440, 2441, 2442 for every compared method. Do not pick the best seed.
- ImageNet initialization in every real experiment. Random initialization is used only in the artificial software test.
- Batch 16, max 25 epochs, 2 head-only epochs, patience 6, AdamW head/backbone LR 1e-4/1e-5, decay 1e-4. BatchNorm running statistics remain frozen.
- Each seed's checkpoint is selected by validation AUROC; BCE breaks ties. Mean validation AUROC across the same three seeds selects a method; mean AP breaks ties. Include Brier score, sensitivity/specificity, camera counts and error examples when interpreting it.
- Screening threshold: highest specificity at >=90% validation sensitivity. This is fitted separately on validation for each trained model and is optimistic on that selection sample.
- No class weighting/oversampling, target-dataset adaptation, temperature calibration or additional architecture search in this initial experiment plan.
- All classification-eligible development images remain in the classifier, even if a mask is invalid. Anatomy loss applies only to segmentation-eligible rows. Empty/non-nested masks marked eligible cause an error rather than being silently repaired.
- Auxiliary validation masks support validation anatomy monitoring, never classification input. CDR targets use exported segmentation-mask bounding extents/areas, so describe them as mask-derived geometric measurements rather than calibrated physical measurements.
- No CHAKSU-test or PAPILA image is opened by this runner. It reads the frozen manifest's metadata to check partition integrity, then constructs datasets only for train/validation.

**Prior test exposure:** baseline CHAKSU/PAPILA results have already been seen. New choices informed by their failure modes make later results on those datasets exploratory/reused-test evidence. A new untouched cohort or prospectively held-out data is needed for independent confirmation. Meet to select by development results, not the largest PAPILA AUROC. Do not describe a team-wide search across many branches as independent test validation.

The historical baseline used a previous runner and emitted nondeterminism warnings. E0 is a fresh matched reference, not a promise of bitwise reproduction of the old epoch-8 model. The current CuBLAS setting is recorded. Each complete run records source snapshots, hashes, Git state, resolved packages, threshold, and checkpoint identity.

## Run on the existing HPC setup

Use the existing remote folder `~/projects/glaucoma_cnn_baseline_bundle` with its intact `artifacts/`. Upload both `hpc_experiments/` and `splits/` from the supplied run bundle into this root. The experimental runner is self-contained: a small frozen subset of legacy baseline utilities is stored as `hpc_experiments/baseline_utils.py`, with its source commit identified. Existing shared project modules are not modified. Create a separate environment `.venv-indira` so experiments do not change the old baseline/team environment.

```bash
cd ~/projects/glaucoma_cnn_baseline_bundle
curl -fL https://bootstrap.pypa.io/virtualenv.pyz -o /tmp/indira_virtualenv.pyz
python3 /tmp/indira_virtualenv.pyz .venv-indira
source .venv-indira/bin/activate
python -m pip install --upgrade pip
python -m pip install torch==2.9.1 torchvision==0.24.1 --index-url https://download.pytorch.org/whl/cu126
python -m pip install -r hpc_experiments/requirements.txt
python -c "from torchvision.models import resnet18, ResNet18_Weights; resnet18(weights=ResNet18_Weights.IMAGENET1K_V1); print('ResNet weights ready')"
cd hpc_experiments
python -m unittest test_experiments.py
cd ..
```

The artificial checks train short reference/fusion models on generated pixels and verify saved-checkpoint inference. They are not glaucoma experiments, and their random metrics must not enter the report.

**Preflight first** (may be run on the login node; it validates development files without training):

```bash
python hpc_experiments/train.py --experiment E4 --seed 2440 \
  --manifest splits/all.csv \
  --artifacts artifacts --check-only
```

This requires real binary `disc_segmentation.png`/`cup_segmentation.png` files referenced by the manifest in addition to prepared RGB images. Missing/zero-byte/corrupt masks must be restored from the intact export. The local Mac download contained zero-byte prepared files; do not train from that copy or regenerate split assignments to work around it. The original local pipeline manifests also contained truncation; use the saved effective manifest specified above.

**Stage 1: three primary configurations, first seed**:

```bash
mkdir -p logs
sbatch --array=0,3,6%1 hpc_experiments/run_array.slurm
```

Array mapping: 0/1/2 = E0 seeds 2440/2441/2442; 3/4/5 = E3; 6/7/8 = E4; 9/10/11 = E1; 12/13/14 = E2; 15/16/17 = E5. `%1` requests at most one task running at a time. The GPU partition and resource options assume the lab's previously working setup; change only if the lab requires it.

If all three runs finish and their outputs are valid, complete the other planned seeds **without choosing them based on first-seed scores**:

```bash
sbatch --array=1,2,4,5,7,8%1 hpc_experiments/run_array.slurm
```

Optional secondary experiments, if resources/time permit:

```bash
python -c "from torchvision.models import efficientnet_b0, EfficientNet_B0_Weights; efficientnet_b0(weights=EfficientNet_B0_Weights.IMAGENET1K_V1); print('EfficientNet weights ready')"
sbatch --array=9-17%1 hpc_experiments/run_array.slurm
```

Each submission returns its own job ID. Monitor using `squeue -u "$USER"`; inspect `logs/indira_JOBID_TASKID.out` and `.err` using the real IDs. Do not blindly rerun a completed array; the summary tool rejects multiple real runs for the same experiment and seed to prevent accidental cherry-picking. A failed run retains `failure.txt` and `status.json`; inspect the cause before retrying.

## Compare and bring evidence to the meeting

Run after training jobs have ended:

```bash
python hpc_experiments/summarize.py --runs hpc_experiments/runs \
  --output hpc_experiments/results/meeting_01
```

This writes an experiment log, mean/SD comparison table, and within-seed differences for the specified controlled comparisons. It does not create missing runs or treat a single-seed result as a completed three-seed comparison. Standard deviations across seeds are not confidence intervals for patient performance. Validation estimates are selection-dependent; extensive tuning on 28 positives is a material limitation.

Each run saves:

- `config.json`, `provenance.json`, `pip_freeze.txt`, code snapshots and `model.json`;
- `history.csv`, checkpoint `best.pt`, `summary.json` and completion/failure status;
- validation metrics, camera metrics, calibration/ROC/PR curves, learning curves and image-level predictions;
- anatomy target hashes, predictions and validation MAE for E3/E4/E5;
- a validation false-negative/false-positive image gallery.

Record clinical failure categories in `error_review_template.csv`: illumination/quality, disc size, possible physiological cupping, coexisting pathology, uncertain reference, or other. These are review labels, not automatic causal explanations. Have a knowledgeable reviewer assess clinical categories. Do not claim that a visible feature caused the network's decision.

Before publishing logs or image-level outputs, review filenames and data-sharing constraints. Run directories (including checkpoints, images, and predictions) are Git-ignored. Commit aggregate comparison tables and a concise finding/next-action entry on this branch. Do not commit `.venv/`, datasets, checkpoints or image galleries. Preserve all full run artifacts in approved team storage.

## Sources

Predicted-anatomy supervision/fusion is this project's experimental design; no state-of-the-art performance or guaranteed improvement is claimed.
